# MioKit.WebSearch 后续候选

当前版本已具备：独立的历史/收藏全局搜索开关、Command 空查询列表、模板名称直达、跨来源网址合并、结果链接操作、Profile 导入失败时保留旧记录，以及 SQLite 依赖和设置页资源打包。已落地的 Feature 与属性见 [features-and-properties.md](features-and-properties.md)。

## 搜索体验

- 当前 SQL `LIKE` 是直接子串匹配，不支持拼音、模糊匹配或搜索语法。全局搜索开启后，应先测量大索引上的按键延迟，再评估索引方案。
- 浏览历史与收藏的 `SearchResult.OwnerObject` 仍是共享节点，因此没有逐网址图标。历史访问时间已显示，但宿主的统一评分不会直接采用每条记录的访问时间或次数。
- 输入本身是网址时没有“直接打开”结果；自定义网站也尚未接入别名、置顶、热键和忽略搜索等通用 Feature。
- 搜索模板的“输入优先，空时使用剪贴板”策略在全局空查询时不会触发，因为网站搜索组会跳过空输入；如需此能力，应明确首页空查询的展示方式。

## 浏览器索引与隐私控制

- 目前只发现 Edge、Chrome、Firefox；设置页仅展示已发现 Profile，尚不能逐个启停、显示友好名称或清除单个来源缓存。
- 索引每 5 分钟全量重建，每个 Profile 最多导入 5 万条历史。后续可增加同步耗时、每来源条数和增量策略。
- Chromium 的数据库与 WAL/SHM 文件逐个复制，活跃浏览器写入时可能得到不一致副本。失败时现会保留该来源旧记录，仍可进一步评估 SQLite 在线备份方案。

## 界面与宿主边界

- 设置页的网站列表显示图标缓存状态，尚未预览实际 favicon；前端 URL 预览仍有一套独立的 `{query}` 替换逻辑。
- 结果操作已由插件提供。当前 SDK 文档称宿主在附着 Command 后不会打开 Alt 操作菜单；需在目标宿主版本验收，若仍受限则由宿主开放附着搜索结果的菜单。
- favicon 刷新任务及手动索引任务尚未统一纳入插件停止流程；刷新中的旧网站图标也可能与更新后的图标竞争写入。
